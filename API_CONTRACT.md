# BugLens AI — FastAPI Backend API Contract

This document specifies the exact API contract expected by the **BugLens AI** frontend (`AI Coding Debugger — BugLens AI`).
The backend developer must adhere to these endpoint paths, schemas, and status codes to ensure seamless integration.

---

## 1. Environment & Network Configuration

### Base URL
The frontend reads the API base URL exclusively from the environment variable:
```env
VITE_API_BASE_URL=http://127.0.0.1:8000
```
- For cross-laptop communication over a local network, set this to the backend host's local IP address (e.g. `http://192.168.1.45:8000`).
- **Security Notice:** Do not include API secret tokens or private keys in `VITE_` variables, as they are exposed to the client bundle.

### FastAPI CORS Configuration
Because the frontend runs on a distinct origin (typically `http://localhost:5173` or `http://127.0.0.1:5173`), the FastAPI backend must enable CORS middleware in `main.py`:

```python
from fastapi import FastAPI
from fastapi.middleware.cors import CORSMiddleware

app = FastAPI(title="BugLens AI Backend", version="1.0.0")

app.add_middleware(
    CORSMiddleware,
    allow_origins=[
        "http://localhost:5173",
        "http://127.0.0.1:5173",
        "*"  # Recommended for hackathon local-network testing
    ],
    allow_credentials=True,
    allow_methods=["*"],
    allow_headers=["*"],
)
```

## 2. Standard Types & Enums

### `VerificationStatus` (string)
- `"Suggested"`: Fix is generated by AI but not yet verified.
- `"Validated"`: Fix has passed dry-run or static validation.
- `"Tests Passed"`: Fix passed all test assertions in the sandbox runner.
- `"Tests Failed"`: One or more sandbox test assertions failed.
- `"Not Verified"`: Status is unverified or inconclusive.

> **CRITICAL RULE:** Do not return `"Validated"` or `"Tests Passed"` for newly suggested code until actual validation or tests have succeeded.

### `ErrorCategory` (string)
One of:
- `"Syntax"`
- `"Runtime"`
- `"Logic"`
- `"Type"`
- `"Boundary Condition"`
- `"Unknown"`

### Endpoint 1: Health Check
- **Path:** `/api/health`
- **Method:** `GET`
- **Purpose:** Verifies backend connectivity, version, and isolated sandbox runner availability.

#### Request
No request body or parameters.

#### Response Schema
| Field | Type | Required / Optional | Description |
|---|---|---|---|
| `status` | string | **Required** | `"healthy"` or `"ok"` |
| `version` | string | *Optional* | Backend API semantic version (e.g. `"1.0.0"`) |
| `sandbox_available` | boolean | *Optional* | `true` if isolated execution service is active; `false` otherwise (default `true`) |
| `message` | string | *Optional* | Status or diagnostic message |

#### HTTP Status Codes
- `200 OK`: Service operational.
- `503 Service Unavailable`: Backend or dependency offline.

#### Example Response
```json
{
  "status": "healthy",
  "version": "1.0.0",
  "sandbox_available": true
}
```

### Endpoint 2: Debug Code
- **Path:** `/api/debug`
- **Method:** `POST`
- **Purpose:** Primary debugging endpoint. Analyzes buggy code, classifies the error, pinpoints root cause and line number, generates a proposed fix with diff-ready code, beginner explanation, and test suggestions.

#### Request Schema
| Field | Type | Required / Optional | Description |
|---|---|---|---|
| `language` | string | **Required** | Programming language (`"python"`, `"javascript"`, `"java"`, `"cpp"`) |
| `code` | string | **Required** | Buggy source code snippet |
| `error_description` | string | *Optional* | User description or runtime stack trace |
| `expected_behavior` | string | *Optional* | Desired output or functional requirement |
| `stdin` | string | *Optional* | Standard input for the program |
| `test_cases` | array of objects | *Optional* | Array of `{ "input": string, "expected_output": string }` |

#### Request Example
```json
{
  "language": "python",
  "code": "def add(a, b):\n    return a - b\n",
  "error_description": "Expected addition but received subtraction",
  "expected_behavior": "Return the sum of a and b",
  "stdin": "",
  "test_cases": [
    {
      "input": "2,3",
      "expected_output": "5"
    }
  ]
}
```

#### Response Schema
| Field | Type | Required / Optional | Description |
|---|---|---|---|
| `session_id` | string | *Optional* | Unique session identifier for history tracking |
| `detected_issue` | string | **Required** | Concise summary of the detected problem |
| `error_category` | string (`ErrorCategory`) | **Required** | One of `"Syntax"`, `"Runtime"`, `"Logic"`, `"Type"`, `"Boundary Condition"`, `"Unknown"` |
| `root_cause` | string | **Required** | Deep root-cause diagnosis |
| `affected_line` | number \| null | **Required** | 1-based line number of the faulty code, or `null` if general |
| `explanation` | string | **Required** | Technical explanation of the bug mechanism |
| `recommended_fix` | string | **Required** | Overview of the fix recommendation |
| `corrected_code` | string | **Required** | Complete corrected source code ready for diffing and replacement |
| `verification_status` | string (`VerificationStatus`) | **Required** | Must be `"Suggested"` for initial debug responses |
| `assumptions_and_uncertainty` | array of strings \| string | *Optional* | Assumptions made by AI model |
| `suggested_additional_tests` | array of objects | *Optional* | Additional `{ "input": string, "expected_output": string }` edge cases |
| `explain_like_learning` | string | *Optional* | Accessible beginner-friendly conceptual explanation |
| `quality_suggestions` | array of strings | *Optional* | Code quality, readability, and lint suggestions |
| `execution_result` | object | *Optional* | `{ "stdout": string, "stderr": string, "exit_code": number, "execution_time_ms": number }` |

#### HTTP Status Codes
- `200 OK`: Analysis successfully completed.
- `400 Bad Request`: Empty or invalid payload.
- `422 Unprocessable Entity`: Validation failure on parameters.
- `429 Too Many Requests`: Rate limit exceeded on AI provider.
- `500 Internal Server Error`: Backend processing or AI engine failure.
- `503 Service Unavailable`: AI service unreachable.

#### Response Example
```json
{
  "session_id": "ses_8f92a1",
  "detected_issue": "Incorrect arithmetic operator",
  "error_category": "Logic",
  "root_cause": "The minus operator '-' is used instead of '+' in the return statement.",
  "affected_line": 2,
  "explanation": "The function returns 'a - b' which calculates the difference between a and b rather than their sum.",
  "recommended_fix": "Replace '-' with '+' in the return expression.",
  "corrected_code": "def add(a, b):\n    return a + b\n",
  "verification_status": "Suggested",
  "assumptions_and_uncertainty": [
    "Assumes standard numeric inputs (integers or floats)"
  ],
  "suggested_additional_tests": [
    {
      "input": "-1, 5",
      "expected_output": "4"
    }
  ],
  "explain_like_learning": "In Python, the '+' operator adds numbers together, while '-' subtracts them.",
  "quality_suggestions": [
    "Add type annotations: def add(a: int, b: int) -> int:"
  ]
}
```

### Endpoint 3: Validate Fix
- **Path:** `/api/validate-fix`
- **Method:** `POST`
- **Purpose:** Performs dry-run or static verification of the proposed fix against user requirements.

#### Request Schema
| Field | Type | Required / Optional | Description |
|---|---|---|---|
| `language` | string | **Required** | Programming language |
| `original_code` | string | **Required** | Original buggy source code |
| `corrected_code` | string | **Required** | Proposed corrected source code |
| `expected_behavior` | string | **Required** | Target requirements |

#### Request Example
```json
{
  "language": "python",
  "original_code": "def add(a, b):\n    return a - b\n",
  "corrected_code": "def add(a, b):\n    return a + b\n",
  "expected_behavior": "Return the sum of a and b"
}
```

#### Response Schema
| Field | Type | Required / Optional | Description |
|---|---|---|---|
| `is_valid` | boolean | **Required** | `true` if the fix satisfies requirements without introducing syntax/logic defects |
| `verification_status` | string (`VerificationStatus`) | **Required** | `"Validated"`, `"Suggested"`, or `"Not Verified"` |
| `validation_details` | string | **Required** | Technical validation feedback or dry-run log |
| `runtime_output` | object | *Optional* | `{ "stdout": string, "stderr": string, "exit_code": number }` |
| `feedback` | string | *Optional* | Additional feedback comments |

#### HTTP Status Codes
- `200 OK`: Validation completed.
- `400 Bad Request`: Missing code fields.
- `422 Unprocessable Entity`: Invalid parameters.
- `500 Internal Server Error`: Validation engine error.

#### Response Example
```json
{
  "is_valid": true,
  "verification_status": "Validated",
  "validation_details": "Fix satisfies expected addition behavior and passes AST validation without side effects.",
  "runtime_output": {
    "stdout": "Dry run check passed",
    "exit_code": 0
  }
}
```

### Endpoint 4: Run Tests
- **Path:** `/api/run-tests`
- **Method:** `POST`
- **Purpose:** Executes test assertions against the submitted code in the isolated sandbox runner.

#### Request Schema
| Field | Type | Required / Optional | Description |
|---|---|---|---|
| `language` | string | **Required** | Target language |
| `code` | string | **Required** | Code to execute |
| `test_cases` | array of objects | **Required** | Non-empty array of `{ "input": string, "expected_output": string }` |

#### Request Example
```json
{
  "language": "python",
  "code": "def add(a, b):\n    return a + b\n",
  "test_cases": [
    {
      "input": "2,3",
      "expected_output": "5"
    },
    {
      "input": "-1,1",
      "expected_output": "0"
    }
  ]
}
```

#### Response Schema
| Field | Type | Required / Optional | Description |
|---|---|---|---|
| `all_passed` | boolean | **Required** | `true` if 100% of test cases passed |
| `passed_count` | number | **Required** | Number of assertions passed |
| `total_count` | number | **Required** | Total assertions executed |
| `results` | array of objects | **Required** | Individual test case results (see table below) |
| `execution_time_ms` | number | *Optional* | Total execution time in milliseconds |
| `verification_status` | string (`VerificationStatus`) | **Required** | `"Tests Passed"` if `all_passed === true`; otherwise `"Tests Failed"` |

##### `results` Item Schema
| Field | Type | Required / Optional | Description |
|---|---|---|---|
| `input` | string | **Required** | Test input argument(s) |
| `expected_output` | string | **Required** | Expected output string |
| `actual_output` | string | **Required** | Actual stdout or returned output |
| `passed` | boolean | **Required** | Whether this assertion passed |
| `error_message` | string | *Optional* | Runtime exception or assertion error |
| `execution_time_ms` | number | *Optional* | Execution time for this specific assertion |

#### HTTP Status Codes
- `200 OK`: Tests executed in sandbox.
- `400 Bad Request`: No test cases provided or invalid syntax.
- `422 Unprocessable Entity`: Parameter validation error.
- `500 Internal Server Error`: Execution environment error.
- `503 Service Unavailable`: Sandbox runner unavailable.

#### Response Example
```json
{
  "all_passed": true,
  "passed_count": 2,
  "total_count": 2,
  "results": [
    {
      "input": "2,3",
      "expected_output": "5",
      "actual_output": "5",
      "passed": true,
      "execution_time_ms": 12
    },
    {
      "input": "-1,1",
      "expected_output": "0",
      "actual_output": "0",
      "passed": true,
      "execution_time_ms": 10
    }
  ],
  "execution_time_ms": 22,
  "verification_status": "Tests Passed"
}
```

### Endpoint 5: Get History
- **Path:** `/api/history`
- **Method:** `GET`
- **Purpose:** Retrieves previous debugging session records.

#### Request
No request body or parameters.

#### Response Schema
The frontend accepts either a direct array: `HistorySession[]` OR a wrapped object: `{ "sessions": HistorySession[] }`.

##### `HistorySession` Item Schema
| Field | Type | Required / Optional | Canonical Name | Notes |
|---|---|---|---|---|
| `id` | string | **Required** | `id` | Unique session ID (e.g. `"ses_001"`). See field compatibility note below. |
| `timestamp` | string | **Required** | `timestamp` | ISO 8601 string (e.g. `"2026-10-19T10:30:00Z"`) |
| `language` | string | **Required** | `language` | Language identifier |
| `error_description` | string | **Required** | `error_description` | Short problem description |
| `error_category` | string (`ErrorCategory`) | **Required** | `error_category` | `"Syntax"`, `"Runtime"`, `"Logic"`, `"Type"`, `"Boundary Condition"`, `"Unknown"` |
| `original_code` | string | **Required** | `original_code` | Original code snippet. See field compatibility note below. |
| `corrected_code` | string | *Optional* | `corrected_code` | Corrected code if fix was generated |
| `verification_status` | string (`VerificationStatus`) | **Required** | `verification_status` | Verification status badge |
| `root_cause` | string | *Optional* | `root_cause` | Diagnosed root cause |
| `status` | string | *Optional* | `status` | Session lifecycle state |

#### Field Compatibility & Integration Note:
- **`id` vs `session_id`:** The frontend contract expects `id`. If your database models this field as `session_id`, please alias it as `id` or ensure both are present in the response.
- **`original_code` vs `code_snippet`:** The frontend contract expects `original_code`. If your database models this field as `code_snippet`, alias it as `original_code`.

#### Response Example
```json
[
  {
    "id": "ses_8f92a1",
    "timestamp": "2026-10-19T10:30:00Z",
    "language": "python",
    "error_description": "Expected addition but received subtraction",
    "error_category": "Logic",
    "original_code": "def add(a, b):\n    return a - b\n",
    "corrected_code": "def add(a, b):\n    return a + b\n",
    "verification_status": "Tests Passed",
    "root_cause": "Minus operator used instead of plus",
    "status": "completed"
  }
]
```

### Endpoint 6: Delete History Session
- **Path:** `/api/history/{session_id}`
- **Method:** `DELETE`
- **Purpose:** Deletes a specific debugging session record.

#### Request
- **Path Parameter:** `session_id` (string) — ID of the session to delete.

#### Response Schema
| Field | Type | Required / Optional | Description |
|---|---|---|---|
| `success` | boolean | **Required** | `true` if successfully removed |
| `message` | string | *Optional* | Confirmation message |

#### HTTP Status Codes
- `200 OK`: Session deleted.
- `404 Not Found`: Session ID does not exist.
- `500 Internal Server Error`: Deletion failure.

#### Response Example
```json
{
  "success": true,
  "message": "Session ses_8f92a1 deleted successfully"
}
```

### Endpoint 8: Get Benchmark Items
- **Path:** `/api/evaluation/benchmark`
- **Method:** `GET`
- **Purpose:** Retrieves individual benchmark test cases for table display and CSV export.

#### Request
No request body or parameters.

#### Response Schema
Accepts a direct array: `BenchmarkItem[]` OR wrapped object: `{ "benchmarks": BenchmarkItem[] }`.

##### `BenchmarkItem` Schema
| Field | Type | Required / Optional | Description |
|---|---|---|---|
| `id` | string | **Required** | Benchmark case ID |
| `name` | string | **Required** | Human-readable test title |
| `language` | string | **Required** | Language identifier |
| `category` | string (`ErrorCategory`) | **Required** | Category |
| `difficulty` | string | **Required** | `"Easy"`, `"Medium"`, or `"Hard"` |
| `original_code` | string | **Required** | Buggy benchmark code |
| `expected_fix` | string | **Required** | Target fix snippet |
| `status` | string | **Required** | `"Passed"`, `"Failed"`, or `"Inconclusive"` |
| `execution_time_ms` | number | *Optional* | Execution time in milliseconds |
| `tested_at` | string | *Optional* | ISO 8601 timestamp |
| `notes` | string | *Optional* | Explanatory benchmark notes |

#### Response Example
```json
[
  {
    "id": "bm_001",
    "name": "Binary Search Boundary Overflow",
    "language": "python",
    "category": "Boundary Condition",
    "difficulty": "Medium",
    "original_code": "def binary_search(arr, target):\n    low, high = 0, len(arr)\n    while low <= high:\n        mid = (low + high) // 2\n        if arr[mid] == target:\n            return mid\n    return -1",
    "expected_fix": "def binary_search(arr, target):\n    low, high = 0, len(arr) - 1\n    while low <= high:\n        mid = low + (high - low) // 2\n        if arr[mid] == target:\n            return mid\n    return -1",
    "status": "Passed",
    "execution_time_ms": 14,
    "tested_at": "2026-10-19T09:15:00Z",
    "notes": "Handles high pointer off-by-one boundary"
  }
]
```

## 4. FastAPI Pydantic Models Quick Reference

The backend team can define these Pydantic schemas in `models.py`:

```python
from typing import List, Optional, Dict, Any, Union
from pydantic import BaseModel, Field

# ----------------- Health -----------------
class HealthResponse(BaseModel):
    status: str
    version: Optional[str] = "1.0.0"
    sandbox_available: Optional[bool] = True
    message: Optional[str] = None

# ----------------- Debug -----------------
class TestCaseModel(BaseModel):
    input: str
    expected_output: str

class DebugRequest(BaseModel):
    language: str
    code: str
    error_description: Optional[str] = ""
    expected_behavior: Optional[str] = ""
    stdin: Optional[str] = None
    test_cases: Optional[List[TestCaseModel]] = []

class ExecutionResultModel(BaseModel):
    stdout: Optional[str] = None
    stderr: Optional[str] = None
    exit_code: Optional[int] = None
    execution_time_ms: Optional[int] = None

class DebugResponse(BaseModel):
    session_id: Optional[str] = None
    detected_issue: str
    error_category: str  # Syntax, Runtime, Logic, Type, Boundary Condition, Unknown
    root_cause: str
    affected_line: Optional[int] = None
    explanation: str
    recommended_fix: str
    corrected_code: str
    verification_status: str = "Suggested"
    assumptions_and_uncertainty: Optional[Union[List[str], str]] = None
    suggested_additional_tests: Optional[List[TestCaseModel]] = None
    explain_like_learning: Optional[str] = None
    quality_suggestions: Optional[List[str]] = None
    execution_result: Optional[ExecutionResultModel] = None

# ----------------- Validate Fix -----------------
class ValidateFixRequest(BaseModel):
    language: str
    original_code: str
    corrected_code: str
    expected_behavior: str

class ValidateFixResponse(BaseModel):
    is_valid: bool
    verification_status: str  # Validated, Suggested, Not Verified
    validation_details: str
    runtime_output: Optional[Dict[str, Any]] = None
    feedback: Optional[str] = None

# ----------------- Run Tests -----------------
class RunTestsRequest(BaseModel):
    language: str
    code: str
    test_cases: List[TestCaseModel]

class TestCaseResultModel(BaseModel):
    input: str
    expected_output: str
    actual_output: str
    passed: bool
    error_message: Optional[str] = None
    execution_time_ms: Optional[int] = None

class RunTestsResponse(BaseModel):
    all_passed: bool
    passed_count: int
    total_count: int
    results: List[TestCaseResultModel]
    execution_time_ms: Optional[int] = None
    verification_status: str  # Tests Passed, Tests Failed

# ----------------- History -----------------
class HistorySession(BaseModel):
    id: str
    timestamp: str
    language: str
    error_description: str
    error_category: str
    original_code: str
    corrected_code: Optional[str] = None
    verification_status: str
    status: Optional[str] = None
    root_cause: Optional[str] = None

class DeleteSessionResponse(BaseModel):
    success: bool
    message: Optional[str] = None

# ----------------- Evaluation -----------------
class CategoryBreakdown(BaseModel):
    total: int
    success: int
    rate: float

class EvaluationSummary(BaseModel):
    total_evaluated: int
    successful_fixes: int
    failed_fixes: int
    inconclusive_results: int
    fix_success_rate: float
    execution_success_rate: float
    by_category: Dict[str, CategoryBreakdown]
    by_language: Dict[str, CategoryBreakdown]

class BenchmarkItem(BaseModel):
    id: str
    name: str
    language: str
    category: str
    difficulty: str  # Easy, Medium, Hard
    original_code: str
    expected_fix: str
    status: str      # Passed, Failed, Inconclusive
    execution_time_ms: Optional[int] = None
    tested_at: Optional[str] = None
    notes: Optional[str] = None

# ----------------- Languages -----------------
class SupportedLanguage(BaseModel):
    id: str
    name: str
    sandbox_supported: bool
    version: Optional[str] = None
    monaco_id: str
    notes: Optional[str] = None
```
